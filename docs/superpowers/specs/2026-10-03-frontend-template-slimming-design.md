## 2. 方案选择

| 方案                                                    | 做法                                                                                                                                     | 影响                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **A：删除明确排除的功能，可选页面移出默认源码（推荐）** | 删除注册、社交链路；Demo、AI、工作流、外部控制台和代码生成页面移到 `extensions/`，默认不扫描、不引用、不打包；可复用组件及必要源码保留。 | 默认范围清楚，恢复时有完整源码，维护成本适中。       |
| B：可选模块留在 `src`，增加构建开关                     | 同时维护页面扫描、组件扫描、类型检查、依赖注册和模块开关。                                                                               | 可以切换构建，但当前需求不需要多种包，容易漏掉引用。 |
| C：删除全部不用的源码                                   | 可选功能也删除，以后从 Git 历史或上游找回。                                                                                              | 文件最少，但恢复与上游对照成本较高。                 |

采用 A。第一轮不建立插件系统，也不新增一套业务框架。默认开发和生产前端使用相同的基础功能范围；代码生成等开发工具也须按恢复说明显式启用。

| 模块       | 移出的原始目录                                                                                                                                   |

| 代码生成   | `src/views/tool/gen/`、`src/api/tool/gen/`。开发模板 `gen/` 保留。                                                                               |

保存方式：需要退出的页面按模块放入 `extensions/<module>/src/...`，保留原目录层级；各模块说明记录原位置、依赖、环境变量、菜单权限及后端启用条件。已封装的可复用组件优先留在原位置；可选页面目录内的表单、弹窗等子组件随页面保存完整源码。保留组件需要的资源留在原位置，其他页面专用资源随页面移出。

`extensions/` 是恢复用源码，不是第二个可直接启动的项目。默认入口不得导入该目录；页面扫描、组件自动导入、类型检查、样式和资源扫描不得纳入它。保留在 `src` 的组件及 API/types 继续参加类型检查，但没有默认页面引用，不进入默认运行调用链。恢复时按说明将页面源码放回原目录，再恢复引用和配置，并核对后端、菜单和角色权限；仅增加菜单不能启用模块。

MCP 当前没有专用前端入口，不新增清理工作。

## 6. 路由、菜单与消息同步调整

### 6.1 动态路由和旧菜单

当前 `src/store/modules/permission.ts:14` 使用 `import.meta.glob('./../../views/**/*.vue')`，菜单隐藏后页面仍会进入构建。因此先移出可选页面，再核对静态 import、自动组件声明和全局注册，保证退出页面与当前不用的组件实现不进入默认产物。组件扫描或生成类型声明不等同于运行时引用，不能为减少声明而删除可复用组件。

在生成侧边栏、顶部菜单、默认路由和注册路由之前，用同一份已退出模块清单过滤后端返回菜单。以已核对的组件路径、菜单路径和专用权限标识识别退出模块，避免按中文名称判断。处理被过滤后变空的目录，以及指向已退出页面的重定向；保留 `Layout`、`ParentView`、`InnerLink` 和合法的基础菜单、外链。

未在退出清单中、却找不到组件的菜单，记录明确诊断并排除无效路由，不让用户进入空白页。菜单搜索使用过滤后的路由；历史书签访问已退出模块时按现有 404 规则处理。

新数据库应使用精简后端的基础初始化脚本。已有库的旧菜单可由前端兼容过滤，但这不等于数据库菜单和授权已清理，也不替代服务端权限校验。本轮不删除已有库数据。

### 6.2 消息盒子

- 默认只展示“系统”和“通知”，退出“工作”页签及流程跳转。
- 保留 `MessageBoxVO.workflowList` 和推送分类解析，兼容后端现有返回结构，不改后端合同。
- 对初次消息加载和实时推送使用相同规则：流程消息不进入默认可展示消息集合，不计入未读数，也不触发流程弹窗或跳转。
- “全部已读”只处理默认展示的系统、通知消息，不把隐藏的流程消息一并标为已读。
- 系统、通知消息的跳转目标如果属于退出模块，保留消息内容与已读功能，提示页面未启用；正常通知目标仍能跳转。
- 保留当前 SSE/WebSocket 连接方式、重连和退出时关闭连接的行为。

主要涉及 `src/layout/components/notice/index.vue`、`src/utils/push.ts`、`src/utils/push-message.ts`、`src/store/modules/notice.ts` 和 `src/api/system/message/types.ts`。

1. `pnpm exec vue-tsc --noEmit`、`pnpm lint`、`pnpm build` 通过，确认本轮文件格式符合 oxlint/oxfmt 约定。
