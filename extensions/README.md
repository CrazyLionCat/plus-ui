# 可选前端页面恢复说明

这些页面保留完整源码，默认应用不引用、不扫描、不构建 `extensions/`。这里只保存恢复材料，没有独立运行入口。

| 模块       | 保留位置                                            | 默认状态                                         |
| ---------- | --------------------------------------------------- | ------------------------------------------------ |
| Demo       | demo/src/views/demo、demo/src/api/demo              | 退出                                             |
| AI         | ai/src/views/ai、ai/src/api/ai                      | 退出                                             |
| 工作流     | workflow/src/views/workflow                         | 退出；Process 组件和 workflow API/types 仍在 src |
| 外部控制台 | consoles/src/views/monitor/{admin,snailjob,snailai} | 退出                                             |
| 代码生成   | gen/src/views/tool/gen、gen/src/api/tool/gen        | 退出；根目录 gen/*.ftl 保留                      |

恢复步骤：

1. 在非生产环境选择需要的模块，先启用对应后端能力及数据。
2. 将选中模块的 `src/` 子目录按原层级复制回项目 `src/`，不要覆盖已有业务改动。
3. 按模块说明恢复环境变量和闲置插件注册；需要的依赖已保留。
4. 从 `src/utils/template-scope.ts` 的路径、组件和权限过滤清单中移除该模块。恢复工作流时还需恢复消息展示规则及工作页签。
5. 恢复菜单、按钮权限和角色授权。菜单来自后端；恢复前端源码不能替代后端启用。
6. 先构建生成自动导入声明，再运行类型检查、lint、测试及实际联调。可选源码不在默认类型检查范围，不能把默认构建通过当作恢复模块已通过。

可复用组件继续保留在 `src/components/`，即使目前未被基础页面引用，也不删除。专用业务调用仍需要匹配的后端能力。
